# Edit labels

Load settings first: `uv run ${CLAUDE_PLUGIN_ROOT}/scripts/overlay.py show` (see `setup`). Commands below use `lsctl` for `uv run ${CLAUDE_PLUGIN_ROOT}/scripts/labelstudio.py`; it needs the token in the variable named by `LABEL_STUDIO_TOKEN_ENV` (inject it with the user's secrets tool; never write it to a file). Writes are dry runs until `--confirm`.

## Steps

1. `lsctl get-config <pid> -o /tmp/ls-<pid>.xml` and `lsctl label-usage <pid>` (count of each label value per control in existing annotations).
2. Classify the change:
   - **Add** a label or choice: safe. Give it a hotkey and colour that don't clash.
   - **Recolour, reorder, hotkey**: safe.
   - **Remove an unused value** (usage 0): safe.
   - **Remove or rename a used value, merge two, or rename a control `name`**: Label Studio refuses a config that drops a value
     still in annotations or drafts. This is a migration:
     a. `lsctl export <pid> -o <data folder>/exports/<pid>-<date>.json` (backup first, always);
     b. add the new value alongside the old (`set-config`);
     c. rewrite each affected annotation result (`PATCH /api/annotations/<id>` with the edited `result`), checking the count matches `label-usage`;
     d. remove the old value (`set-config`, which now validates).
     Say how many annotations change and get a yes before step c.
   - **Cosmetic rename**: keep the stored value and change only the display (`alias` on a Label, `html` on a Choice).
3. Apply with `lsctl set-config <pid> /tmp/ls-<pid>.xml`, then `--confirm`.
4. If results are written back to a dataset, check the export script and any training code that lists label values
   (search the project repository for the old value) and update them in the same change.

## Notes

- Choices with `allowNewChoice` don't need a config change to add values, but the new value then lives only in annotations: add it to the config afterwards.
- Projects generated by a script: change the script's label list, not just the project.

## Data storage

Writes exports and config backups under `<data folder>/exports/` and `config-history/`.
